Introduction

Git is a powerful, distributed version control system designed to track changes in source code and other files, enabling multiple developers to collaborate on a project effectively and efficiently. It allows users to maintain a complete history of revisions, branch and merge workflows, and work offline without relying on a central server. With Git, developers can experiment, manage codebases of all sizes, and ensure the integrity and consistency of their projects through features like commit histories, branching, and conflict resolution.

VCS

A version control system (VCS) is a tool used to track changes in files over time, enabling collaboration, rollback of changes, and better management of code or document versions. It is commonly used in software development but can be applied to any set of evolving files.

  • Local: All changes are stored on the local computer, and the version history is maintained only within the user's system.
  • Centralized: There is a single central server where all changes and version history are stored. Users check out files, make changes, and commit them back to the server.
  • Distributed: Each user has a full copy of the repository, including its entire version history. This allows users to work offline and provides redundancy, as every copy can act as a backup.

    dnf install git # Fedora

  • macOS:

    brew install git

    Or download the installer from the official website.

Repository

A repository is where all project information is stored...

git init

or

git init <repository name>
Commit

A commit is a snapshot of the changes in the repository...

git add *

Then save these changes to the repository:

git commit -m "First commit"
Branch

A branch is an independent line of development...

git branch <branch name>

To switch to a different branch:

git checkout <branch name>
Merge

A merge is the combination of two branches...

git checkout main

Then perform the merge:

git merge new-branch
